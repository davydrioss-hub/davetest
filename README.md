# After Hours — private co-op prototype

Рабочий сетевой прототип для Windows x64 на Godot **4.4.1**. Игровая сцена — небольшой 3D-двор курьерской службы. Это проверяемая основа из присланного multiplayer-ТЗ, а не готовый симулятор открытого мира.

## Играть

1. Распакуйте **весь** архив `AfterHours-Windows.zip`. Запустите `AfterHours/AfterHours.exe`. Файл `AfterHours.pck` должен оставаться рядом.
2. При первом запуске введите ник.
3. Хост: **PLAY → HOST GAME**. Укажите имя сервера, 2/4/8 игроков (включая хоста), пароль по желанию. Для нового мира выберите **NEW WORLD** и уникальное имя, затем **START GAME**.
4. Друзья: **PLAY → JOIN GAME**, адрес хоста, например `192.168.1.50:27020`, пароль и **CONNECT**.
5. Для продолжения хост выбирает свой мир в списке **LOAD**. Друзья подключаются снова.
6. Одиночный режим: **PLAY → SINGLE PLAYER**. Используется та же серверная симуляция; сетевой порт не открывается.

Для игроков не нужны Godot, Python, Steam, Epic, аккаунт, отдельный сервер или установка магазина. GitHub нужен только для разработки, если вы решите хранить там исходники.

## Подключение

Порт по умолчанию: **UDP 27020**; его можно изменить в меню хоста. LAN-адреса хоста показаны внизу формы HOST GAME. Разрешите входящие подключения игре в брандмауэре Windows для используемой сети.

Через интернет используйте публичный адрес хоста и перенаправление **UDP** выбранного порта с маршрутизатора на компьютер хоста. Одного публичного IP без доступного входящего порта недостаточно. При CGNAT это обычно требует услуги публичного адреса от провайдера; другой вариант — виртуальная LAN/VPN и адрес хоста в ней. Автоматических matchmaking, relay, NAT traversal и UPnP в прототипе нет. Протокол работает по UDP и не шифрует игровой трафик; для шифрованного соединения используйте доверенную VPN.

Без интернета работают одиночный режим и обычная LAN. Нельзя подключаться к адресу `192.168…` через интернет без маршрута в эту сеть. На каждом компьютере должна быть одна и та же версия игры.

## Управление и тестовая игра

| Клавиша | Действие |
|---|---|
| WASD | Ходить; за рулём — ехать и поворачивать |
| E | Подобрать посылку, взять припас, открыть ворота, сесть/выйти из машины, купить депо, нанять сотрудника |
| F | Сдать свою посылку в зелёной зоне Dispatch, получить $250 |
| Q | Положить посылку на землю |
| T | Вернуть припас в контейнер рядом |
| R | Возродиться после 3-секундной задержки |
| F5 | Сохранить мир (хост) |
| Esc | Меню сессии: продолжить, сохранить, выйти |

В мире восемь посылок и восемь одноразовых заказов. Начальный баланс — $300. Депо стоит $600; сотрудник стоит $150 и приносит $25 каждые 30 секунд работающей сессии. Красная площадка DANGER специально проверяет смерть/возрождение. При смерти инвентарь сохраняется. NPC и патруль показывают репликацию серверной симуляции; боевой ИИ и система преступлений не реализованы.

Когда клиент выходит, прогресс остаётся у хоста. Выход хоста завершает сессию с сообщением **Host disconnected.** Миграция хоста не реализована.

## Сохранения и идентичность

Windows: `%APPDATA%\Godot\app_userdata\After Hours\`

```text
identity.key              # персональный приватный ключ этого компьютера
profile.cfg               # ник, настройки, Recent Servers без паролей
Saves/World01/world.sav    # только у владельца мира
Saves/World01/world.sav.bak # предыдущее целое сохранение
```

PlayerID вычисляется из локального публичного ключа: `Player_` + 32 шестнадцатеричных символа. ENet PeerID меняется при подключении и никогда не используется как постоянная личность. Сервер проверяет подпись одноразового challenge; один ник или скопированный PlayerID не дают доступ к чужому прогрессу.

Не передавайте друзьям свою `identity.key`. Архив игры не содержит никаких персональных профилей. Для переноса **своего** прогресса на другой ПК перенесите свой профиль; два клиента с одним ключом одновременно не допускаются. Если ключ потерян, сервер увидит нового игрока. Хосту для резервной копии нужны и профиль, и папка Saves.

Автосохранение: раз в 30 секунд, после подключения/отключения игрока и перед выходом хоста. Аварийное завершение процесса может потерять изменения после последнего успешного сохранения. Все домены записываются **одной транзакцией** в `world.sav`, а не несколькими несогласованными файлами; используются временный файл, SHA-256 и резервная копия. При неисправном сохранении новый мир автоматически не генерируется.

## Разработка

Откройте `project.godot` в Godot 4.4.1 Standard (GDScript). Других библиотек и плагинов не требуется.

```text
scripts/profile.gd      Локальная личность и настройки
scripts/session.gd      ENet, handshake, snapshot/delta, проверки RPC, подключение
scripts/world_state.gd  Чистая серверная симуляция и игровые правила
scripts/save_store.gd   Версионированная атомарная запись и восстановление
scripts/world_view.gd   3D-представление реплицированного мира
scripts/main.gd         Меню, HUD и отправка ввода
tests/                 Проверки правил и реальные отдельные ENet-процессы
```

**Authority:** все игроки, предметы, деньги, заказы, свойства контейнеров, двери, машина, свойства депо, сотрудник, NPC, патруль и время изменяются у хоста. Клиент отправляет намерение движения или действие с идентификатором объекта. Сервер сам определяет отправителя, допустимую дистанцию, право владения, лимиты, баланс и результат.

Симуляция 60 Гц; вход движения 30 Гц; репликация поз игроков и занятой/движущейся машины 20 Гц. NPC-пакеты — 5 Гц, далёкая симуляция упрощается примерно до 1 Гц. Двери, заказы и инвентари отправляются надёжными дельтами при изменении. Начальный полный snapshot содержит стабильные идентификаторы и состояние существующего мира; клиенты создают только его визуальное представление. Протокол отделяет каналы ввода/поз, NPC и надёжных событий. Версии мира/ревизии предотвращают применение устаревших поз после сброса позиции.

Машина — простая кинематическая модель с одним водителем. Это не синхронизация физического движка и не реалистичная автомобильная физика. Перед релизом полноценной игры следует добавить конкретные игровые механики, контент, профилирование, тесты на разных Windows-ПК/реальных сетях и компенсацию задержки. Предсказания движения на клиенте пока нет; по WAN отклик зависит от пинга. Функциональность рассчитана на частную игру с доверенными друзьями, а не публичную серверную инфраструктуру.

## Проверки и сборка

```sh
godot --headless --path . res://tests/core_tests.tscn
python tests/network_tests.py /path/to/godot
python tools/build_windows.py
```

Последняя команда скачает официальные Godot 4.4.1 и Windows-шаблон экспорта, затем создаст `build/AfterHours-Windows.zip`. Для разработчика нужен Python 3.10+ и интернет. Если нужные инструменты уже скачаны: `python tools/build_windows.py --godot /path/to/godot --template /path/to/windows_release_x86_64.exe`.

В исходники включён GitHub Actions workflow, который собирает архив и запускает тесты. Он не публикует релиз и не отправляет уведомления от имени пользователя. Тестовые драйверы исключены из Windows-экспорта.
